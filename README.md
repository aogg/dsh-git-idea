# dsh-git-idea

照着 IDEA 的 VCS 做的 Git 集成，装进 DSH 会话：输入框「**权限模式**」旁边一个 Git 图标 —— 显示当前分支与未提交改动数，**悬停**切分支，**点击**弹出 IDEA 风格的面板（分支树、提交历史与提交图、变更与暂存、提交详情、文件差异、三方合并冲突解决），顶栏还有一个**配置页**，分**项目配置**（多仓库时编辑哪个仓库由页首的「仓库」组挑，默认眼前仓库）与**全局配置**（提交身份、换行符、git 位置、网络参数）两档。

**不向 DSH 注册任何模型工具**（模型要跑 git 本来就有 `bash`，见[不注册工具](#不注册工具)）。
**面板属于会话，不属于窗口**：同一页面里的每个会话各看各的工作区。

> Git integration for DeepSeek Harness, modelled on IDEA's VCS — a git icon beside the permission mode in the composer (branch + pending count), a branch switcher on hover, an IDEA-style VCS panel on click, and a config tab with project and global scopes. Registers no model tools with DSH.

## 安装

要求 DSH `>=0.1.5-rc.1`（只声明最低版本；peer：`@deepseek-ai/cordis ^4.0.2`）。DSH 0.1.7 把执行器的一次性 `run(spec)` 换成了 `execute(spec)` 加 `result()`，Host 那一半两种形状都认 —— 0.1.5/0.1.6 和 0.1.7+ 装的是同一份包。0.1.7 的 `sessions.get` 也只回答活着的会话，解析会话工作区时会退到 `sessionPersistence` 读会话头，刚选中、还在恢复的会话因此也能读到。

```sh
dsh plugin --profile web add dsh-git-idea                    # npm
dsh plugin --profile web add github:mays-hi/dsh-git-idea      # GitHub
dsh plugin --profile web add /path/to/dsh-git-idea            # 本地
```

装完**重启 `dsh web`**。报 `ERR_PNPM_ADDING_TO_ROOT` 就在包名前加 `-w`。

> 已经跑着旧版动态插件（`<DSH_HOME>/dsh-git-idea` 那个桥）就先停掉 —— 两个都装着就是两份 chip、两个面板抢同一个 slot。

## 用法

### chip（输入框「权限模式」旁边那个 Git 图标）

| 操作 | 结果 |
|---|---|
| 看 | 当前分支 + 未提交文件数（`工作区干净` / `3 个改动`） |
| 悬停 | 分支切换卡片，点一下切过去（可在设置里关） |
| 点击 | 开 / 收面板 |

### 面板

```
变更 3 │ 历史 │ 命令 │ 配置    ⟳ ⇣ ↓ ↑    feature-risk ↑2 ↓1    树 扁平
─────────────┬──────────────────────┬──────────────────────
分支树        │ 变更树 / 提交列表      │ 差异 / 提交详情 /
HEAD 本地 远程 │                      │ 提交信息与提交按钮
```

| 区域 | 内容 |
|---|---|
| 顶栏 | `变更`（带数量）/ `历史` / `命令` / `配置` 页签；`⟳` 重读、`⇣` fetch、`↓` pull、`↑` push（带领先/落后角标）；中间是当前分支，点开切换器；右端「树 / 扁平」切换变更页视图 |
| 左栏 | 分支树：`HEAD` / `本地` / `远程`（每个远端各一个 `远程 · <名字>` 子组），带搜索、收藏、排序；行尾 `›` 是该分支的动作（检出、从此分支新建分支、合并到当前分支、删除） |
| 中栏 | `变更` 页是工作区，`历史` 页是提交列表 + 提交图 |
| 右栏 | 差异 patch / 提交详情 / 提交信息与提交按钮 |

![历史页：分支树、提交列表、提交详情](docs/panel-history.png)

*`历史` 页：左边分支树（`HEAD` / `本地` / `远程`），中间提交列表与提交图，右边是选中提交的详情、改动文件与提交信息。*

![变更页：勾选文件、写提交信息、暂存或提交](docs/panel-changes.png)

*`变更` 页：没跟踪的文件也在树里（红色 `?`）；右边写提交信息，下面是「全部暂存并提交（N 项）」和「全部暂存」，右上角切「树 / 扁平」。*

合并、拣选、stash pop 等留下未解决冲突时，冲突文件不再和普通修改混在一起：它们单独聚在变更页顶部的「冲突」组，红色加粗的双码（`UU`、`AA`、`DU`…）一眼可辨，组头下一行灰字说明解法；右栏提交区也会先提醒「N 个冲突未解决，直接提交会被 git 拒绝」。点击冲突文件打开的不是普通差异，而是[三方合并界面](#三方合并解决冲突)。

点开文件后的差异是**左右对比**：左列旧行、右列新行，各带行号；连续的删除块与新增块按行配对并排摆，多出的一侧留空，`@@` 与 `\ No newline` 行横跨两列。配成对的行再做**词级高亮**——两侧各自把行内差异的片段用同色系更浓一档的浅底包住（左红右绿），行太长或 token 太多就整行原样。头部「回车符」勾选框把行尾的 CR 画成暗色 `⏎` 并让它参与词级对比，CRLF↔LF 的差别一眼可见；勾选状态记在这个浏览器里，切换只重画已拿到的补丁，不重新读 git。

「命令」页是这个工作区里跑过的 git 命令（会话记录 + 面板执行的记录，只读，不碰仓库）：面板一**打开**就在后台预读，不用先切到这一页（面板藏着时不发读）；之后的每个刷新时机 —— 切到这一页、这一页开着时仓库动过（⟳、fetch、提交、会话完成那一刷都算）、点「重新读取」—— 都走同一条后台路：手里已有列表就绝不清空、绝不置「正在读取」（只有这个会话第一次生成才显示「正在读取命令记录…」），读完按行身份增量合并 —— 屏上只多出新的几行、正在跑的行补上真退出码，同一行重读多少遍都还是一行，展开状态跟着行走。后台刷新在飞时条数旁挂一句轻的「刷新中…」；手里有列表时读失败了，列表照常能用，错误原话挂在列表上方，下一次读成了它自己消失。

### 三方合并解决冲突

PHPStorm 风格：标题是 `合并 <仓库> 的 <相对路径> 的修订`，从上到下是顶部工具栏、三栏只读对比、可编辑的结果区、底部按钮。

* **三栏只读**：左 ours「来自 <分支> 的更改」、中 base「基准版本」、右 theirs「来自 <分支> 的更改」，拖任意一栏三栏一起滚。标签尽力解析：merge 场景 ours=当前分支名、theirs=`MERGE_HEAD` 指向的分支名；拣选、stash pop 等解析不出就退化为「本地更改 / 传入的更改」，绝不因此报错。
* **顶部工具栏**：`↓` `↑` 在冲突块间循环跳转（结果区滚到那一块并高亮）；`↶` 撤销只作用于结果区；「应用不冲突的更改」把没撞车的区域重新自动合并进结果（已做的选择原样保留）；`<< 左侧` / `右侧 >>`（及「所有」款）把当前/全部冲突块整体采用某一侧并去掉标记；`⚙` 关掉本界面并打开面板的「配置」页（本插件在 DSH 全局设置面板里没有自己的一页，这是面板内能到的设置类页面）。
* **右上角计数**实时更新：没动过结果区时「没有更改，N 个冲突」，动过之后「N 个冲突」，全部解决后「全部已解决（0 个冲突）」。N = 结果区里还没做出选择的冲突块数 —— 手动删掉一块的三行标记就算这一块已解决。
* **结果区**进入时已按「应用不冲突的更改」的语义预填（无冲突区域自动合并，冲突块以 `<<<<<<<` / `=======` / `>>>>>>>` 呈现），可以手改任何内容，全文就是要写盘的内容。冲突相关的行各有底色：左栏改动蓝、右栏改动黄、基线灰、未解决的块红。
* **底部按钮**：「应用更改」（蓝）＝结果区全文写回该文件并 `git add` 标记已解决，然后刷新回变更列表；还有未解决的块时也允许点，但会先确认（说明那些块会以标记原样写入）。「取消」只关界面、一个字节不写，也**绝不执行 `git merge --abort`** —— 合并是你在命令行或面板别处发起的，这个界面不拥有合并过程，只管这一个文件。
* **边界**：AA（两侧各自新增）中栏显示「两侧各自新增，无基准版本」，整个文件是一块冲突；DU/UD（一侧删除）缺的一侧显示「该侧已删除此文件」，接受该侧＝整块删除；打开前已被解决/仓库已变、文件超过 1.2 MB、二进制文件、子模块冲突，都给一句明确的话而不是空白。
* 冲突块怎么算出来在客户端自带的 diff3（patience 对齐 + 按 git xdl_merge 的口径分组：改动的 base 区间贴着也算重叠），与 `git merge-file` 对过 400 例随机差分，git 判干净的合并逐字节一致。

面板的边角可拖动，尺寸记得住。

### 常见动作

| 想做什么 | 怎么做 |
|---|---|
| 提交 | `变更` 页勾选 → 右栏写提交信息 → 「全部暂存并提交（N 项）」或「全部暂存」 |
| 只提交一部分 | 只勾那几个文件；再点一次勾选框 = 取消暂存 |
| 写到一半的提交信息 | 自动按生效仓库存进部署配置 `dsh-git-idea.json`（换浏览器/换机器打开同一工作区还在；输入停手约一秒存一次，提交前立刻存一次）。提交成功后输入框**不清空** —— 连续提交沿用同一条；真想要空框，点输入框旁的 ×，清空也会被记住。切仓库/开面板时草稿只填进空框，框里已有的字一个字节不动 |
| 看某个文件的改动 | 在变更树或提交详情里点该文件，patch 占满正文，左上角箭头返回；头部路径前有和列表行同一只勾选框（勾 = 这个文件的改动进了索引，点一下走暂存/取消暂存；提交详情那一路没有它）。要看整个文件时点头部右上角的「查看文件」，它在 DSH 官方右侧的文件页里打开这个文件 —— 打开的永远是工作区里的当前内容（提交那一路也一样），服务不在（老版 DSH）或路径不在会话工作区内时这个按钮不出现 |
| 切分支 | 点顶栏分支名（或悬停 chip）→ 选分支 → 检出。切换器的「远端」按远端各成一组（`远端 · origin`、`远端 · upstream`…，origin 优先）：远端分支**全量在列**，本地已有同名分支的也显示，两个远端的同名分支是两行、行尾小字各写各的远端；搜索既匹配短名也匹配完整名（搜 `upstream` 只剩那一组）。远端行的检出是显式的 `git switch -c <分支> --track <远端>/<分支>`（多远端下 DWIM 短名切换会被 git 以 "'x' is ambiguous" 拒掉）；本地已有同名分支时不发请求，先提示「本地」组里那一行就是它。左栏分支树右键「远程」组的分支「签出」遇本地同名分支时弹窗二选一：直接切到本地分支（保留本地提交），或用远端覆盖（`git switch` + `git reset --hard`，本地独有提交与未提交改动丢弃） |
| 新建分支 | 切换器底部「新建分支」，可从某个提交或分支起；分支行右键 →「新建分支…」（以该分支为起点）；提交行右键 →「从这个提交新建分支…」 |
| 合并 / 拣选 / 还原 | 分支行 `›` → 合并到当前分支；**提交行右键** → 拣选 / 还原（对右键那一条生效，Ctrl 多选不受影响） |
| 打标签 | **提交行右键** →「打标签…」→ 填名字 |
| 复制分支名 | **分支行右键** →「复制分支名称」（本地、远程行都可以）。剪贴板写不进时分支名会亮进提示条，手动复制 |
| 删除分支 | **本地分支行右键** →「删除分支」（再点一次确认；当前分支置灰不给自己删）；`-d` 被拒（提交没合并到别处）时出现「强制删除（-D）」，也要再确认一次。远程分支行只有复制，不提供删除 |
| 拉取 / 推送 | 顶栏 `⇣ ↓ ↑`，分支卡里的 `↓ ↑` 同一件事；push 没有上游时右栏给出「推送并设为上游」（设置开着「自动设上游」时，推送失败后还会自动补推一次）。要替你挑远端时（横幅按钮、自动补推）按同一条规则：**origin 优先 → 仓库恰好只有一个远端就用它 → 都不满足就不猜** —— 多远端而无 origin 时横幅只留一句提示，请用分支行右键「修改跟踪分支…」指定。pull 在分支没有上游时自动兜一步：远端有**同名分支**就直接绑定（`--set-upstream-to`）并拉取，成功条写明绑到了哪个（多个远端都有同名时 origin 优先，无 origin 取字母序第一个）；没有同名就弹出**远端分支选择层**（按远端分组、可搜索，分支卡里就地出现），选中后绑定并拉取；绑定撞上远端分支其实不存在（列表过期）时自动回到选择层重挑。detached HEAD、还没出生的分支照旧直接 pull，不加配置开关 |
| 管理远端 | 顶栏「配置」页「远端」组：**添加多个**远端（名字 + 地址，成功后框清空接着添）、**改地址**（行内编辑，回车保存）、**删除**（再点一次确认）；动作记进「命令」页，成功后面板整体刷新，分支树的「远程」分组跟着变 |
| 冲突 | 顶栏横幅「正在合并：N 个文件冲突」+ 继续 / 跳过 / 中止；解决并暂存后点继续 |
| 看/解决合并冲突 | 冲突文件聚在变更页顶部「冲突」组（红色 `UU`/`DU`…）；点击打开三方合并界面逐块解决，应用＝写回并 git add 标记已解决（见[三方合并解决冲突](#三方合并解决冲突)）；或手动编辑后勾选暂存 |
| 搜索历史 | 默认字面匹配，`.*` 切正则，`Cc` 区分大小写；`分支:` `作者:` 时间 路径 各是一个筛选 |
| 更早的提交 | 列表底部「加载更多」，一次 200 条 |

### 提交被 git 拒了

`git commit` 要署名，而名字和邮箱写在 **git 自己的配置里**，不在仓库里。这台机器没配过时，提交会被 git 拒绝。

两条路，都留着：面板 **配置 → 全局配置 → 提交身份** 里填一次，或者在终端里跑

```sh
git config --global user.name "你的名字"
git config --global user.email "你的邮箱"
```

（不加 `--global` 只对当前仓库生效。）面板不会替你署名 —— 署谁的名字只有你知道 —— 但它会在提交区**先说**这件事，被拒之后把上面那两条原样写出来，连 git 自己最后一行一起。写完之后不用重启，下一次读取（30 秒的时钟，或任意一次暂存 / 提交）就不再提醒。

同一类失败不只出现在「提交」上：拣选、还原、合并的继续、pull 都要造提交对象，它们走同一个判据（`git var GIT_AUTHOR_IDENT`，也就是 `git commit` 自己拼身份时走的那条路，任何语言下都是同一个退出码）；而 `git add`、`git branch -d`、中止这些在没有身份的机器上照跑，面板不会把它们说成身份问题。

### 看哪个仓库

只看**会话工作区那一个目录**，且 `<dir>/.git` 必须存在 —— 不向上找父目录，也不往里看子目录。
引导页可以改成别的目录：「打开这个目录」进那个路径；那里还不是仓库时旁边有「在此初始化仓库」（`git init`，默认分支见设置）。

#### 多仓库（工作区里嵌着好几个仓库）

一个工作区里嵌着多个仓库时（monorepo 里各自独立的 `.git`、旁边 clone 的参考项目），分支树顶部与变更页左侧各有一个**仓库列表**（配置页的项目档也挂着同一份清单 —— 那里单击是挑「本页在编辑哪个仓库」，见[配置页](#配置页项目配置--全局配置)）：

* 面板首次打开时异步扫一遍工作区（所有子孙层级的 `.git`，跳过 `node_modules` 等依赖目录，深度与数量有上限），清单落地后补进列表，不阻塞首帧；每个工作区只自动扫一次。
* 「＋ 添加目录」可手动登记一个仓库路径，**跟随项目持久化**（存部署配置 `dsh-git-idea.json` 的 `repos`，换浏览器/换机器打开同一工作区仍是同一份）；被删掉的目录显示为「已不存在」，可一键移除，不会崩。
* **单击**某个仓库 = 把它设为**生效仓库**：右侧历史、chip、提交、推送全部跟着换（即上面的单仓库行为）；「全部」= 所有仓库一起显示。
* 单击选定的生效仓库**按工作区记进部署配置** `dsh-git-idea.json` 的 `appliedRepos`（一区一格，键=工作区绝对路径）：换浏览器、换机器、开新会话都还是它 —— 生效仓库跟的是这个工作区，不再跟会话走。单击即存（同值重申也存，盖掉别的浏览器留下的旧账）；每个会话的 chip 挂载时向后端问一次（`git/repo-applied`），本页已亲手点过的不覆盖；记下的仓库已不存在时不套用（`stale`），等下次单击自然覆写。浏览器 localStorage（键 `dsh.git-idea.applied-repos`）降级为首帧快速通道：后端答复落地前先按它画，落地以后端为准。
* **Ctrl+单击**多选（或点「全部」）只影响所在那一栏的显示：左栏分支树按仓库分组显示各仓库的分支，变更页的变更树按仓库分组、页签徽章显示合计；历史日志、提交详情、chip 仍跟随最近一次单击选定的生效仓库。
* 两栏的选择相互独立：在变更页挑几个仓库看改动，不会动历史页的分支树。
* 扫描顺带分辨每仓库 `.git` 的类型：是**文件**（worktree / 子模块的 gitlink）的仓库，行旁挂一枚暗色 `wt` 小标 —— 它不是独立仓库。这样的目录落在「不是 Git 仓库」的引导页时，页下会多一块**「worktree 主目录」**：说清它是谁的链接工作区、给出找到的主目录（可一键打开），主仓库被删/搬走时手填一个新位置存进部署配置（`worktreeMains`），面板从此照常可用；配置页「仓库」组里也有同一个条件下级组。详见[功能列表](./docs/功能列表.md)「仓库定位与引导」。

### 配置页（项目配置 / 全局配置）

顶栏第 4 个页签，页首一排切换分两档作用域：**项目配置**管眼前这个项目（排版两块 —— 「会话完成」一组在外，它是插件级开关、不跟编辑目标走；之后「仓库」一大组，顶部挑仓库、受切换仓库影响的提交身份 / 远端 / 换行符三组收在它里面做**下级**：缩进 + 左侧竖线，组头点名当前目标仓库的短名，目标还没读到时退回「这个项目／这个仓库」的泛称；编辑目标是链接工作区时还有一个条件出现的「worktree 主目录」下级组，见下表），**全局配置**管插件与这台机器（见[设置](#设置) —— 原先挂在 DSH 设置面板里的那一页，2026-10 起搬到了这里）：

| 组 | 内容 |
|---|---|
| 会话完成（外框之外，插件级） | 「会话完成时刷新 git 状态」（默认开）：会话跑完那一刻自动做一次 ⟳ 级别的整棵树刷新 —— chip 的分支名/改动数、变更/历史页跟着更新，命令页若开着也重读；刚被会话新建的文件只有全树读能看见，这正是它该刷的时机。「所有会话都完成时自动推送」（默认关）：本页所有会话（含子代理会话）都停止运行且稳定 5 秒后，对当前生效仓库 push 一次（等同顶栏 ↑；生效仓库是「仓库」组列表里带 ● 的那行，**不随本页正在编辑的仓库走**）；只推「领先远端且没有未解决冲突」的分支，失败只记录不重试，结果说在「最近一次自动推送」那行 |
| 仓库（这一页在编辑哪个仓库）—— 大组，下面三个 ↳ 小组收在它里面 | 与历史/变更页**同一份**多仓库清单（工作区扫描 + 手动登记 + 「已不存在」）。单击行只换**本页**的编辑目标：组内收着的提交身份、远端、换行符读写的都是它，请求里明说仓库路径；默认编辑目标 = 当前生效仓库（带 ● 的行）。单击**不改面板的生效仓库** —— 历史、提交、推送还作用在原来那个上，要换生效仓库去历史/变更页的仓库列表。「＋ 添加目录」与历史页是同一份持久清单、同一套报错话术，加成功自动把新仓库选为编辑目标；「已不存在」行只可移除、不可选中；会话工作区本身不是仓库时这组照常可用（把嵌着的仓库登记进来就能直接配置它）。名字/邮箱的半截草稿切编辑目标即清 —— 对着上一个仓库打的字不会被写进下一个 |
| ↳ 提交身份（只写 lab 的 .git/config） | 名字与邮箱只写 `--local`；默认空 = 跟随全局，placeholder 显示全局那份的值。顶部一行「此刻生效」带来源文件，缺身份时红色提醒；「清掉本项目覆盖，用回全局」对填过的键逐条 `--unset`（本来就没配也算成功）。全局那份切到页首的「全局配置 → 提交身份」改 —— 那边只写这台机器（`--global`） |
| ↳ 远端（lab 的 remote 清单） | 列出每个远端的 fetch 地址（push 地址不同才一并显示），可**添加多个**（名字 + 地址，成功后框清空接着添）、**改地址**（行内编辑，回车保存）、**删除**（再点一次确认）；动作都记进「命令」页，成功后面板整体刷新，分支树的「远程」分组跟着变。名字不能有空白 |
| ↳ 换行符（lab 的 git 换行配置） | `core.autocrlf`（true / false / input）与 `core.safecrlf`（true / false / warn）两条同样只写选中仓库（`--local`），改动立即生效：autocrlf=true 检出转 CRLF、提交转回 LF，input 只在提交时转 LF，false 不转；safecrlf 是把关开关，换行转换不可逆（行尾抹过一遍还原不回去）时 true 让 git 拒绝、warn 只警告、false 不把关。每条旁边显示此刻生效的值与来源，选「跟随全局」= 清掉该仓库的这条（组头里的 lab 是示例：实际显示当前编辑目标仓库的短名） |
| ↳ worktree 主目录（lab 是链接工作区时才出现） | 本页编辑目标的 `.git` 是链接文件（worktree / 子模块）时多出的下级组：展示主目录与来源（手动配置 / 自动找到 / 目录不在了），可手填主目录「保存」（存 `dsh-git-idea.json` 的 `worktreeMains`，换浏览器/换机器都在）或「清除配置」回到自动识别。主仓库被删/搬走的 worktree 配置过这里就照常能看历史与变更；历史/变更页左栏 worktree 块的「主目录」行是它的捷径（「打开主目录」切生效仓库、「配置…」跳到本组） |

会话状态听的是 DSH 注入的会话 hook（每个会话常驻的 chip 在听，面板关着也在）：bridge 版／老版本没有这些 props 时两条开关不起作用，页面上会明说「当前环境不支持会话状态监听」。

编辑器保存是另一条即时的刷新来路：装着 DSH-better-sidebar（≥ 0.27.0）时，内置编辑器保存文件成功会让本插件失效读缓存，并在约 1.5 秒防抖后广播一次整树刷新 —— 与会话完成那一刷同一条路（见[联动插件](./docs/联动插件.md)）；该插件未安装或版本过旧时这里什么都不发生，零报错，其余照旧。

### 读不动时

每一种理由说自己的话，能做的事不同：

| 情况 | chip | 面板 |
|---|---|---|
| 路径还没定 | 还没确定看哪个目录 —— 点击填写 | 「无法确定要查看的仓库路径」+ 路径框 |
| 路径不存在 | 目录不存在：… —— 点击修改路径 | 「目录不存在」+ 路径框 |
| 路径是个文件 | 这不是一个目录：… —— 点击修改路径 | 「这不是一个目录」+ 路径框 |
| 目录在，不是仓库 | … 这个目录不是 Git 仓库 —— 点击查看 | 「这个目录不是 Git 仓库」+「打开这个目录」/「在此初始化仓库」 |
| git 在，读不动它 | … 读取失败 —— 点击查看原因 | 「git 命令执行失败」+ git 的原话 |
| 机器上没有 git | …：这台机器上找不到 git —— 点击查看 | 同一页改说这件事，路径框和初始化按钮都收起（都不是出路），装好 git 再点「打开这个目录」 |

「不是 Git 仓库」那一页故意没有路径框：路径不是问题，没什么可填的。

## 设置

面板 → **配置 → 全局配置**（原先这里是一页挂在 DSH 设置面板左下角的「dsh-git-idea配置」，2026-10 起整个搬进面板的配置页，与「项目配置」并排成两档）。

**插件级**（写 `$DSH_HOME/dsh-git-idea.json`，默认 `~/.dsh/dsh-git-idea.json`，换浏览器一致）。这份文件在工作区之外，所以它和这个插件改的其它东西走同一条路：能不能写由**这个会话的沙箱策略**决定，写不进去时页面上会明说（而不是安静地什么也没发生）：

| 项 | 默认 | 说明 |
|---|---|---|
| 初始化仓库的默认分支 | `main` | 引导页「在此初始化仓库」执行 `git init -b <值>`；留空用 git 自己的默认值 |
| cherry-pick 时记录来源（`-x`） | 关 | 提交时是否带 `-x` |
| git 位置 | 空（用 PATH 上的 git） | 面板每一条命令都以这一个词开头；装在不在这条 PATH 上的地方（Homebrew 前缀、IDE 自带的 git、nix profile）时写绝对路径。旁边实时显示它解析到哪、什么版本、能不能跑 |
| fetch 时删掉远端已删的远程分支（`--prune`） | 开 | 关掉就是 `git fetch --all` |
| pull 用 rebase（`--rebase`） | 关 | 关掉就是 `git pull`（merge） |
| 推送没有上游的分支时自动设上游（`push -u`） | 关 | 关掉时推送失败后面板问一句「推送并设为上游」 |
| 会话完成时刷新 git 状态 | 开 | 会话跑完那一刻自动做一次 ⟳ 级别的整棵树刷新（监听在 chip 上，面板关着也在）；配置页「项目配置」档有同一对开关 |
| 所有会话都完成时自动推送 | 关 | 本页所有会话（含子代理会话）都停止且稳定 5 秒后，对当前生效仓库 push 一次；只推「领先远端且没有未解决冲突」的分支，失败只记录不重试 |

这三条网络项是**面板给 git 的实参**，不是 git 设置的副本：没勾的就是 git 原本的行为，`push.default`、`pull.rebase` 照旧生效。「远程同步」组底部还照着实参写一遍会执行成什么（`git fetch --all --prune · git pull · …`）。

**git 自己的配置**（不在上面那个 json 里）：全局配置的「提交身份」直接读写 `user.name` / `user.email` 的 `--global` 那份，也就是终端里的 git、IDEA、钩子看到的同一份；它先显示此刻生效的那一份**和它的来源**（`.git/config` 还是 `~/.gitconfig`），落点只有这一个 —— 写进这台机器的 git 配置（`--global`），项目自己的那份归配置页「项目配置」档。空着的框一个字节都不写：`git config user.name ''` 正是「empty ident name」那个错误的来路。「换行符」组管的是同一份 `--global` 里的 `core.autocrlf` / `core.safecrlf`：每条旁边显示当前全局值与来源，选中即写，首项「不设置」＝清掉 `--global` 的这条（DSH 不重启时宿主还没有这两条路由，那一组会给一行「重启 DSH 后才能读写」的说明）。配置页的「项目配置」档也管身份，外加这两个换行键 —— 那边只写 `--local`，管的是眼前这个项目（见[配置页](#配置页项目配置--全局配置)）。

**浏览器级**（只写当前浏览器 localStorage）：

| 项 | 默认 | 说明 |
|---|---|---|
| 后台监测仓库变化并自动刷新 | 开 | 关掉后下面的节奏选项一并失效 |
| 面板打开时每 N 秒检查 | 3（1–120） | |
| 面板关着时每 N 秒检查 | 5（2–600） | 只发一次廉价签名（读者那台机器 0.12s），所以问得比过去勤 —— 15 秒的话，终端里提交完要过十几秒 chip 才改口 |
| 面板关着时也监测 | 开 | 让 chip 的分支名和改动数保持实时 |
| 悬停弹出分支切换卡片 | 开 | |
| 面板尺寸 | 跟随输入框宽度 / 74vh | 可恢复默认 |
| 变更页视图 | 树 | 或平铺列表 |
| 切换器记忆 | — | 可清除最近使用与收藏 |

### 一次「仓库动过了」之后，插件要花多久才排空

这条 RPC 通道**一次只跑一个处理函数**（实测：一次 8 秒的读在飞的时候，连不 spawn 的
`git/flush`、`git/config` 都要等 8 秒才回）。所以一次全树 `git status` 不只是慢，它把
整块 UI 按在那里 —— 读者那台机器上（Windows 挂载的工作区、5093 个文件、全树 status
8.1s 冷 / `-uno` 也要 5.3s）量到过：

| 场景 | 改之前 | 改之后 |
|---|---|---|
| 终端里提交一次（引用变了），面板开着 | 16 条请求，队列 **21.3s** 排空，其中 13s 是两次全树读 | 队列 **0.4s**：面板问屏上那 7 条路径（0.2s），chip 问身份（0.4s）+ 同样那几条路径（Host 那边是同一个问题，只起一个进程） |
| 同样一次，面板关着 | 4 条请求，排空 **11.1s**（chip 一次全树读 10.6s） | 队列 **0.5s**：chip 只问身份 + 上次那些脏路径 |
| 这个仓库这个浏览器第一次看 | 11s+ | 一样要一次全树读（没量过就没有数字），但那一次之后走上面两条 |

屏幕上的样子是「面板反应过来了，chip 还没」—— 面板那条 0.2s 的路径读排在 chip 那条
8–10s 的全树读后面。现在：

* **「工作区有几个改动」全局只有一份读数**（面板量的、chip 量的都写在同一处），
  chip 上那个数字就是面板「变更」页签上那个数字，两块屏幕不可能各说各话；
* 一次 bump 之后只问**屏上那些路径**，整棵树不在那条路上。这里还有个量出来的坑：
  git 把没跟踪的目录折叠成一条，而**那条本身就是自己的子树** —— 再顺手带上「它所在的
  目录」就等于把旁边整棵大树扫一遍。读者那个仓库上：

  | 问哪些路径 | 耗时 |
  |---|---|
  | 7 条（快照里那些路径本身，含 3 条折叠目录） | **280ms** |
  | 12 条（每条再带上它所在的目录） | **6138ms** ← `holox-modules` 一条吃掉了全部 |
  | 9 条（折叠目录不带所在目录） | **295ms** |

  所以折叠目录那条只问它自己；文件的所在目录留着（「旁边新出现的文件」还靠它看见）。
  另外量到一次路径读本身超过 1.5s 时，这个仓库整个收窄成只问那几条路径本身；

* 整棵树有**自己的时钟**，间隔按上一次实测的代价来定：`max(30 秒, 8 × 上次耗时)`，
  上限 5 分钟。快盘上照旧 30 秒一次；读者那台机器上一次 8 秒，于是 64 秒一次 ——
  不再每 30 秒把整条通道冻 8 秒。⟳ 按钮永远立刻整棵树重读一次；
* 还没核对出来的时候 chip 说的是「**正在核对改动…**」，不谎称「工作区干净」。

代价说清楚：**「本来干净、刚刚被改」的那个文件**（以及干净目录里新出现的文件）任何
路径读都看不见，只有整棵树读能看见 —— 它由上面那个时钟兜着，所以最坏情况下要等一个
间隔（快盘 30 秒，慢盘 64 秒）才出现在「变更」页里。⟳ 是立刻拿到它的办法。

## 不注册工具

插件给 DSH 的只有 UI 和它自己的 RPC 通道：39 条 `host.call('git/…')`（面板、chip、配置页走的就是它们）。模型要跑 git 本来就有 `bash`，所以不注册工具。

撤掉那 8 个工具（`git`、`git_status`、`git_log`、`git_diff`、`git_commit`、`git_branch`、`git_stash`、`git_sync`）时量到的：

| 量到的 | 数 |
|---|---|
| 8 个工具的 schema | **7210 字节／每次请求**（约 1800 token，与这一轮是否碰 git 无关） |
| 只为它们存在的 Host 代码 | **约 908 / 2577 行（35%）**：`40-tools` 533 行、`20-safety` 中 160 行、`30-render` 中 215 行 |
| 客户端调用工具的次数 | **0** —— 面板只走 `host.call('git/…')`，撤工具对 UI 零影响 |

代价：`git_diff` 原先把差异渲染成 GUI 里的原生 diff 卡，现在记录里只有文本。

## 开发

源码按功能拆片段，构建就是按顺序拼接，没有转译、打包或压缩。改代码改 `src/`。

```sh
node build-package.mjs          # 正式包：lib/index.js + client/client.js
node build.mjs                  # 动态桥：host.js + client.js
node test/run-all.mjs           # 全部断言（1327 条）
node build.mjs --check && node build-package.mjs --check   # 产物是否最新
node test/bench.mjs             # 基准：200 条提交的历史列表
node test/bench-branch.mjs      # 基准：300 个分支的切换器
```

`test/run-all.mjs` 跑断言前先检查三样东西是否落后于源码：动态桥产物、正式包产物、每个套件文件。
