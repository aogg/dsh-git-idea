# dsh-git-idea 功能列表

> 详细用法见 [README.md](../README.md)。

## 概览

- 在 DSH 输入框「权限模式」旁提供 Git 图标（chip），点击弹出 IDEA 风格的 VCS 面板；面板顶栏的「配置」页分「项目配置 / 全局配置」两档，全局档管插件本身。
- 不向 DSH 注册任何模型工具：模型要跑 git 本来就有 `bash`。
- 面板属于会话而不属于窗口，同一页面里每个会话各看各的工作区。

## chip（输入框 Git 图标）

- 显示当前分支与未提交文件数（如「工作区干净」「3 个改动」）。
- 悬停弹出分支切换卡片，点一下切过去（可在设置里关）。
- 点击开 / 收面板。
- 面板关着时也按节奏监测仓库变化，让分支名和改动数保持实时。
- 改动数还没核对出来时显示「正在核对改动…」，不谎称「工作区干净」。

## 面板（布局与顶栏）

- 顶栏页签：`变更`（带数量）/ `历史` / `命令` / `配置`。
- 顶栏按钮：`⟳` 重读、`⇣` fetch、`↓` pull、`↑` push（带领先 / 落后角标）。
- 顶栏中间显示当前分支，点开切换器；右端「树 / 扁平」切换变更页视图。
- 左栏分支树分 `HEAD` / `本地` / `远程` 三组（每个远端各一个 `远程 · <名字>` 子组），带搜索、收藏、排序；行尾 `›` 展开该分支的动作。
- 中栏在变更页是工作区变更树，在历史页是提交列表 + 提交图。
- 右栏显示差异 patch、提交详情、提交信息与提交按钮。
- 面板边角可拖动，尺寸记得住。

## 变更 / 暂存 / 提交

- 变更树列出工作区改动，没跟踪的文件也在树里（红色 `?`）。
- 分组标题最左的复选框把整组加进 / 移出索引。
- 勾选 / 再点一次勾选框即对单个文件暂存 / 取消暂存，可只提交一部分文件。
- 右栏写提交信息后可「全部暂存并提交（N 项）」或「全部暂存」。
- 写到一半的提交信息自动按生效仓库存进部署配置 `dsh-git-idea.json`（输入停手约一秒存一次，提交前立刻存一次），换浏览器 / 换机器打开同一工作区还在。
- 提交成功后输入框不清空，连续提交沿用同一条；点输入框旁的 × 清空也会被记住。
- 切仓库 / 开面板时草稿只填进空框，框里已有的字一个字节不动。

## 历史与提交图

- 历史页是提交列表 + 提交图，选中提交在右栏看提交详情与改动文件。
- 搜索历史默认字面匹配，`.*` 切正则，`Cc` 区分大小写。
- `分支:`、`作者:`、时间、路径各是一个筛选。
- 列表底部「加载更多」一次 200 条。
- 双击分支行把历史切到该分支。
- 提交行右键可拣选、还原、打标签、从这个提交新建分支（对右键那一条生效，Ctrl 多选不受影响）。

## 文件差异与查看文件

- 在变更树或提交详情里点文件，patch 占满右栏正文，左上角箭头返回。
- patch 是**左右对比**：左列旧行、右列新行，各带行号沟；连续的删除块与新增块按行配对并排摆（第 i 个删除配第 i 个新增），多出的一侧留空；上下文行左右各一行，`@@` 与 `\ No newline` 说明行横跨两列。长行照旧整块横向滚。
- 行内改动的片段有**词级高亮**：配成对的一行在两侧各自把差异片段用同色系更浓一档的浅底包住（左红右绿）。任一侧超 1000 字符或 token 超上限的行放弃高亮、整行原样。
- 头部有「**回车符**」勾选框（与变更树那只框同一只，默认不勾，状态记在这个浏览器里）：勾上后行尾 `\r` 画成暗色 `⏎`，并参与词级对比 —— 内容相同、只有行尾 CRLF↔LF 差别的一对行，有 `\r` 的那一侧的 `⏎` 会被标出来；不勾时行尾 `\r` 一律剥掉。切换只重画已拿到的补丁，不重新读 git。
- patch 头部路径前有与列表行同一只勾选框（提交详情那一路没有），点一下走该文件的暂存 / 取消暂存。
- 头部右上角「查看文件」在 DSH 官方右侧的文件页打开这个文件，永远是工作区里的当前内容；服务不在（老版 DSH）或路径不在会话工作区内时按钮不出现。

## 分支管理

- 点顶栏分支名（或悬停 chip）打开切换器，选分支 → 检出。
- 切换器底部分组：面板里打开的切换器是 `最近` / `本地` / 每个远端一组（`远端 · origin`、`远端 · upstream`…，origin 优先，其余按名字排，组可折叠）。远端分支**全量在列**——本地已有同名分支的也显示，两个远端的同名分支是两行、行尾小字各写各的远端；搜索既匹配短名也匹配完整名（搜 `upstream` 只剩那一组的行）。对话输入框上悬停弹出的快速切换卡只有 `最近` / `本地` 两组，不列远端分支（收藏了远端分支它也不出现）。
- 远端行的检出是显式的（在面板切换器里）：`git switch -c <分支> --track <远端>/<分支>`（完整远端分支名，不走 DWIM 短名切换——多远端下那会被 git 以 "'x' is ambiguous" 拒掉）；本地已有同名分支时不发请求，先提示「本地」组里那一行就是它。面板左栏分支树右键「远程」组的分支「签出」遇本地同名分支时则是弹窗二选一：直接切到本地分支（保留本地提交），或用远端覆盖（`git switch` + `git reset --hard`，本地独有提交与未提交改动丢弃）。
- 切换器底部「新建分支」可从某个提交或分支起；分支行右键「新建分支…」以该分支为起点。
- 分支行右键「复制分支名称」（本地、远程行都可以）；剪贴板写不进时分支名亮进提示条，手动复制。
- 本地分支行右键「删除分支」，再点一次确认；`-d` 被拒（提交没合并到别处）时出现「强制删除（-D）」，也要再确认一次。
- 当前分支置灰不给自己删；远程分支行只有复制，不提供删除。

## 合并 / 拣选 / 还原 / 打标签 / 冲突入口

- 分支行 `›` 提供检出、从此分支新建分支、合并到当前分支、删除。
- 合并、拣选、stash pop 留下未解决冲突时，冲突文件进入「冲突」组走三方合并界面解决。
- 顶栏横幅「正在合并：N 个文件冲突」提供继续 / 跳过 / 中止，解决并暂存后点继续。
- 提交行右键「打标签…」填名字即打标签。

## 拉取与推送

- 顶栏 `⇣` fetch、`↓` pull、`↑` push（**↑ 单击直接推送当前分支**；右键 ↑ 在光标处弹菜单：直接推送 / 强制推送 / 显示待推送列表），分支卡里的 `↓` `↑` 同一件事。
- 分支行右键「推送」是二级子菜单（悬停展开，仅本地分支行）：「直接推送 / 强制推送」不弹框——远端先取该分支的上游（没有上游按 origin 优先 → 仓库唯一远端现猜，都挑不出上错误条不发请求），发 `git push [--force-with-lease] <远端> <分支>`（不带 `-u`，不顺手改跟踪关系）；「显示待推送列表」走下面的两段式确认。
- **推送前列表确认（两段式）**：顶栏 ↑ 右键菜单与分支行右键推送子菜单里的「显示待推送列表」、右栏「推送并设为上游」先弹确认框，列出将要推送的提交（短 hash、提交说明、作者、相对时间，取自 `git/push-preview`：当前 / 被右键分支领先上游 `@{u}..分支` 的清单，最多 200 条，顶满说明「确认后仍然全部推送」），点「推送」才真正 push；「取消」、Esc、点遮罩都只关框不推。标题即「推送 N 个提交到 origin/main」，同时落后上游 N 个提交时框里提醒先 ↓ 拉取。
- 推送中弹窗不关：确认按钮转圈（`dsh-git-spin`）并显示「推送中…」，取消按钮一并禁用（推到一半没有「取消」可言，Esc / 点遮罩同时失效）；成功关框走正常刷新，失败把 git 原话说在框内、外面错误条同步留一份——「没有上游」那次失败框内自动翻出「推送并设为上游（远端）」的重试按钮，关掉弹窗后右栏横幅照旧。
- 分支还没有上游时弹窗说明情况并走原有选择流程：有 origin（或仓库唯一远端）就按 `git push -u <远端> <分支>` 确认推送；没有远端、或多个远端而没有 origin 时按钮不出现，指路分支行右键「修改跟踪分支…」，不发请求。
- push 失败后右栏仍给出「设置上游并推送」（老行为不变）。
- pull 在分支没有上游时先自动兜一步：远端有同名分支就直接绑定（`--set-upstream-to`）并拉取（多个远端都有同名时 origin 优先，无 origin 取字母序第一个）。
- 没有同名分支时弹出远端分支选择层（按远端分组、可搜索，分支卡里就地出现），选中后绑定并拉取。
- 绑定撞上远端分支其实不存在（列表过期）时自动回到选择层重挑。
- detached HEAD、还没出生的分支照旧直接 pull，不加配置开关。

## 三方合并解决冲突

- 冲突文件单独聚在变更页顶部「冲突」组，红色加粗双码（`UU`、`AA`、`DU`…）一眼可辨，组头下一行灰字说明解法。
- 右栏提交区先提醒「N 个冲突未解决，直接提交会被 git 拒绝」。
- 点击冲突文件打开 PHPStorm 风格的三方合并界面：顶部工具栏、三栏只读对比、可编辑的结果区、底部按钮。
- 三栏为 ours / base / theirs，拖任意一栏三栏一起滚；标签尽力解析（merge 场景 ours=当前分支名、theirs=`MERGE_HEAD` 分支名），解析不出退化为「本地更改 / 传入的更改」，绝不因此报错。
- `↓` `↑` 在冲突块间循环跳转（结果区滚到那一块并高亮）；`↶` 撤销只作用于结果区。
- 「应用不冲突的更改」把没撞车的区域重新自动合并进结果，已做的选择原样保留。
- `<< 左侧` / `右侧 >>`（及「所有」款）把当前 / 全部冲突块整体采用某一侧并去掉标记。
- `⚙` 关掉本界面并打开面板的「配置」页。
- 右上角计数实时更新：没动过结果区「没有更改，N 个冲突」，动过「N 个冲突」，全部解决「全部已解决（0 个冲突）」；手动删掉一块的三行标记就算这一块已解决。
- 结果区进入时已按「应用不冲突的更改」语义预填（无冲突区域自动合并，冲突块以 `<<<<<<<` / `=======` / `>>>>>>>` 呈现），可以手改任何内容，全文就是要写盘的内容。
- 冲突相关行各有底色：左栏改动蓝、右栏改动黄、基线灰、未解决的块红。
- 「应用更改」（蓝）＝结果区全文写回该文件并 `git add` 标记已解决，然后刷新回变更列表；还有未解决的块时也允许点，但先确认（说明那些块会以标记原样写入）。
- 「取消」只关界面、一个字节不写，也绝不执行 `git merge --abort`。
- 边界：AA（两侧各自新增）中栏显示「两侧各自新增，无基准版本」，整个文件是一块冲突；DU/UD（一侧删除）缺的一侧显示「该侧已删除此文件」，接受该侧＝整块删除。
- 打开前已被解决 / 仓库已变、文件超过 1.2 MB、二进制文件、子模块冲突，都给一句明确的话而不是空白。
- 冲突块由客户端自带的 diff3 算出（patience 对齐 + 按 git xdl_merge 的口径分组），与 `git merge-file` 对过 400 例随机差分，git 判干净的合并逐字节一致。

## 手势（与 IDEA 的树一致）

- 目录行（分支树、变更树、提交文件树）单击只选中，双击 / 点三角展开 / 折叠。
- 未跟踪目录（git 折叠成一行的那种）单击只选中不发读取，双击读取并展开。
- 分支行单击只选中，双击把历史切到该分支。
- 分组标题（HEAD / 本地 / 远程）单击只选中，双击展开 / 折叠。
- 文件行单击打开差异；「冲突」组的行打开三方合并界面。
- 分组标题最左的复选框整组进 / 出索引。

## 命令页

- 「命令」页显示这个工作区里跑过的 git 命令（会话记录 + 面板执行的记录，只读，不碰仓库）。
- 面板一打开就在后台预读命令记录，不用先切到这一页（面板藏着时不发读）。
- 刷新时机：切到这一页、这一页开着时仓库动过（⟳、fetch、提交、会话完成那一刷都算）、点「重新读取」。
- 刷新走后台路：手里已有列表就绝不清空、绝不置「正在读取」（只有这个会话第一次生成才显示），按行身份增量合并、正在跑的行补上真退出码，展开状态跟着行走。
- 后台刷新在飞时条数旁挂一句轻的「刷新中…」；手里有列表时读失败列表照常能用，错误原话挂在列表上方，下一次读成了它自己消失。
- 会话扫描有一本按会话文件记的 (mtimeMs, size) 账本（一区一本，内存有界：8 个工作区 LRU、每本 600 文件、只保最新）：账热时打开命令页立即用账答复（实测热答复 18–51ms，全量重扫在 9p 真实工作区是 7–17s），stat 扫描 + 只解析变化文件的增量刷新在后台跑，完成后账若变了经 `cmdlog-refresh` 推送按工作区并回手里的列表；「重新读取」保持强制全量（顺手把账换准）。冷启动与全量扫描一字不差 —— 账本只是缓存，事实源永远是会话文件。
- 每行命令有耗时格：会话行用 tool/call 与 tool/result 两端时间戳相减（拿不到任一端画 —）；面板行开始时画「运行中」，结束推送带着耗时就地换真数字。格式 <1s 毫秒（820ms）、1s–1min 秒一位小数（3.2s）、更长分秒（1m24s）。

## 多仓库

- 一个工作区里嵌着多个仓库时，分支树顶部与变更页左侧各有一个仓库列表；配置页的项目档也挂同一份清单（那里单击是挑「本页在编辑哪个仓库」，见配置页一节）。
- 面板首次打开时异步扫一遍工作区（所有子孙层级的 `.git`，跳过 `node_modules` 等依赖目录，深度与数量有上限），不阻塞首帧；每个工作区只自动扫一次。
- 「＋ 添加目录」手动登记**一个仓库路径、或一个里面嵌着仓库的目录**，跟随项目持久化（存部署配置 `dsh-git-idea.json`：仓库进 `repos`、含仓库目录进与它平行的 `repoDirs`，同一套归一化：数组、绝对路径、去重、封顶）。登记目录自己不必是仓库：每次读清单时在同一条 spawn 里对每个登记目录照跑同一套扫描（同样的跳过名单 / 深度 / 每目录 head 封顶），扫到的子孙仓库照常并入清单，答复新增 `dirs`（登记且还在的目录，排序）与 `dirRepos`（目录 → 子孙仓库）；目录丢了进「已不存在」，可一键移除。移除从 `repos` 与 `repoDirs` 两份清单里幂等地删。
- **列表按容器分组**：登记了含仓库目录、或存在工作区外的手动仓库时按「工作区 → 登记目录（按路径排序）→ 手动登记」分组，组头 = 压暗小字 + 文件夹图标 + 目录短名（悬停见完整路径）；每个仓库归到且只归到一组 —— 在某登记目录下归那个目录（嵌套登记取最长前缀），否则在工作区下归「工作区」，再否则归「手动登记」；空组不画。登记目录的组头带 × 可移除登记，「工作区」「手动登记」组头不带；仓库行的点选、Ctrl 多选、wt 小标、× 删除一律不变。**只够成一组时完全维持平铺渲染**，零视觉回归。
- 单击某个仓库把它设为生效仓库：右侧历史、chip、提交、推送全部跟着换；「全部」＝所有仓库一起显示。
- 单击选定的生效仓库按工作区记进部署配置（`dsh-git-idea.json` 的 `appliedRepos`，一区一格、键=工作区绝对路径）：换浏览器、换机器、开新会话都还是它 —— 不再跟会话走。单击即存（同值重申也存，盖掉别的浏览器留下的旧账）；chip 挂载时向后端问一次，本页已亲手点过的不覆盖，记下的仓库已不存在时不套用（`stale`）；浏览器 localStorage（键 `dsh.git-idea.applied-repos`）降级为首帧快速通道，后端答复落地以后端为准。
- chip 的分支名与分支列表各有一层 localStorage 首帧垫底账（键 `dsh.git-idea.chip-labels` 按会话一格存 `{label, repo, ahead, behind, at}`、`dsh.git-idea.branch-lists` 按仓库一格存 `{data, at}`，与上一条 applied-repos 同一套先例：懒加载一次、读入清洗畸形、LRU 上限 50 会话 / 20 仓库、localStorage 不可用时静默只留内存、不设过期）：刷新页面后内存账全空，chip 在身份快读回来之前先画上次的分支名（含 ↓/↑，同一次身份读的显示垫底），分支卡在 `git/branches` 回来之前先画上次的列表。盘账只管「首帧不空」：快读与列表读每次照发（不拦读、不省读、不加轮询），答复一到即被覆盖；改动数不进缓存，刷新后如实显示「正在核对改动…」。每次成功读到覆写对应格；读到失败答复（不是仓库/目录不存在/git 出错等）删掉该会话的缓存条目并落盘 —— 仓库没了/读不动了，不许在下一次刷新还魂。
- 历史页左栏的三份列表（分支树 `git/refs`——生效仓库一份、多选每仓各一份；worktree 列表 `git/worktrees`；仓库清单 `git/repos` 扫描）有同一款 localStorage 首帧垫底账（63-storedlists.js 通用小工厂，三层：`dsh.git-idea.refs-tree` / `dsh.git-idea.worktrees` 按仓库路径存答复原样 `{data, at}`、LRU 10 仓库；`dsh.git-idea.repo-lists` 按会话存规范化清单 `{repos, manual, missing, links, dirs, dirRepos, note}`、LRU 50 会话；懒加载一次、读入清洗畸形、localStorage 不可用时静默只留内存、不设过期）：刷新后首帧分支树/worktree 块不再空等 RPC，扫描落地前仓库列表不再闪「正在扫描」。盘账只管「首帧不空」：三份读每次照发（不拦读、不省读、不加轮询与定时器），答复一到即被覆盖；答复 `ok:false` 删对应格并落盘（运输层失败不删，Host 回来后下一次刷新垫底还有得上）。
- 同一批读做内容级去重（「有变化才推送」的前端半边）：每条新答复先与内存现账逐字比对（JSON 序列化，宿主键序稳定），一致就不 setState、不重画、不落盘（put 内部再比一次，一致连 LRU 位置都不动）——⟳ 与 watcher 触发的重读在内容没变时不再引发整块重绘。WS 推送面维持原样：宿主（79-live-watch.js）本来就只在仓库签名（refs/HEAD/index 戳）变化时才广播 repo-changed（首次只记基线、空签名不推、2 秒最小间隔），本次不改宿主任何推送语义、不加轮询。
- Ctrl+单击多选只影响所在那一栏的显示：分支树按仓库分组显示各仓库分支，变更树按仓库分组、页签徽章显示合计。
- 历史日志、提交详情、chip 仍跟随最近一次单击选定的生效仓库；两栏的选择相互独立。
- 扫描时顺带分辨每仓库 `.git` 的类型：目录 = 普通仓库，文件 = 链接工作区（worktree / 子模块）——后者的仓库行旁挂一枚暗色「wt」小标（悬停说明「.git 是链接文件（git worktree 或子模块）」），一眼分清哪些行不是独立仓库；「已不存在」行不加标。
- 历史页与变更页左栏的仓库列表正下方各有一个 worktree 块：列出本生效仓库经 `git worktree add` 建出来的链接工作区（单击行 = 历史按它的分支过滤 / 变更列表切到那个工作区；detached / bare / prunable 退灰行，本目录是链接工作区时块头下多一行「主目录」）。块底「＋ 新建 worktree」展开快速创建表单（读取中 / 失败 / 空 / 有清单都在，折叠态不显示）：三选一模式 —— 新建分支（`-b`，「起点」可空 = HEAD，起点给远端分支时 git 自动建立跟踪）、检出分支（本地 ∪ 远端分支提示清单，远端走 git 的 DWIM 自动建同名本地跟踪分支，已被其他 worktree 检出的本地分支照常列出标「已占用」）、游离检出（`--detach`，起点 = 分支 / commit / tag，默认 HEAD）；放置目录必填、预填 = 仓库父目录 + `/` + 仓库名短名 + `-` + 分支短名（`[^A-Za-z0-9._-]+` 折成 `-`，基准目录优先 worktree 主目录、否则生效仓库），可改；「强制覆盖」= `--force`（目录已存在非空 / 分支已被占用 / 目录是已登记但已丢失的 worktree 才需要）；「创建后切到新工作区」默认开（变更页切过去，历史页按新分支过滤，游离只刷新）。提交前用已加载数据免费预检（绝对路径、空字段、目录 / 分支冲突），不过红字拦截不发请求；失败把 host stderr 首行折成人话。走 `git/worktree-add` 一条 RPC（进「命令」页记录），是 worktree 块唯一的写路径 —— prune / remove / lock / move 仍不做。

## 仓库定位与引导

- 只看会话工作区那一个目录，且 `<dir>/.git` 必须存在 —— 不向上找父目录，也不往里看子目录。
- 引导页「打开这个目录」可改成别的目录；那里还不是仓库时旁边有「在此初始化仓库」（`git init`，默认分支见设置）。
- 目录是链接工作区（`.git` 是 gitlink 文件）时，引导页（含「不是 Git 仓库」那页）下面多一块「worktree 主目录」：一句话说清身份、给出找到的主目录与「打开这个目录」，还能手填主目录存进部署配置（`dsh-git-idea.json` 的 `worktreeMains`，换浏览器/换机器都在）；主仓库被删/搬走导致 git 读不动时，配置过主目录的面板照样能用。这块不受该页 editable / init 开关管。
- 面板每次读生效仓库时顺带答一份「worktree 主目录」读数（`git/wt-main`，一次 shell 探测 + 进读缓存）：身份（linked / main / bare / plain / broken-gitlink / missing / file）、gitlink 原文、git 与 gitlink 文本各答的主目录候选、`git worktree list` 全表（带 main / current 标记）。主目录 = 配置值 ?? 自动值，来源（手动配置/自动找到）随答复带出。
- **worktree 目录映射**（全局配置 `worktree` 组，多条「原目录 → 替换目录」）：gitlink 里记的主仓库路径是**别的机器**的（Windows 上建好的 worktree 整棵拷到 Linux，`gitdir: D:/code/…`，Linux 的 git 不认 D: 盘符 → broken-gitlink）时，识别主目录把路径以「原目录」开头的那段整段替换成「替换目录」——前缀按整段匹配（`/data` 配不上 `/database/x`），`D:/…` 与 `D:\…` 两种写法都认，多条先到先得，`worktreeMains` 的手动答案永远压过它。换算成功时答复带 `mainMapped`，各处的来源小字改说「目录映射找到」。范围只到识别层（主目录候选、身份判定、显示）：`.git` 文件一个字节不改、git 调用照旧路由到被探测的目录 —— 面板照旧落在说明页，但那页给的主目录已是本机真在的路径，「打开这个目录」即可用。换算候选的存在性由一次一行补问回答（`[ -e <它>/.git ]`，只在映射真的换了前缀时多发这一问）；没配映射的读者一个进程都不多跑，机器上没有 git 也照样工作（存在性不吃 git）。

## 边界行为

- 路径还没定 / 不存在 / 是个文件 / 不是 Git 仓库 / git 读不动 / 机器上没有 git，chip 与面板各有一句明确的话和对应的出路（路径框、查看原因、打开目录等）。
- 「不是 Git 仓库」那一页故意没有路径框；机器上没有 git 时路径框和初始化按钮都收起，装好 git 再点「打开这个目录」。
- 这台机器没配提交身份时，提交区先说这件事，被拒之后把两条 `git config` 命令和 git 自己最后一行原样写出来。
- 拣选、还原、合并的继续、pull 走同一个身份判据（`git var GIT_AUTHOR_IDENT`）；`git add`、`git branch -d`、中止在没有身份的机器上照跑，不会被说成身份问题。
- 写完身份不用重启，下一次读取（30 秒的时钟，或任意一次暂存 / 提交）就不再提醒。

## 配置页（项目配置 / 全局配置）

- 顶栏第 4 个页签，页首一排切换分两档。「项目配置」管眼前这个项目，排两块：「会话完成」一组在外（插件级，不跟编辑目标走）；之后「仓库」一大组 —— 顶部挑仓库，受切换影响的提交身份、远端、换行符三个小组收在它里面做下级（缩进 + 左侧竖线），编辑目标是链接工作区时还会多出一个「worktree 主目录」下级组，组头点名当前目标仓库的短名（如「提交身份（只写 lab 的 .git/config）」），目标没读到时退回「这个项目／这个仓库」的泛称；「全局配置」管插件与这台机器（见下节）。
- 「worktree 主目录」下级组（条件出现）：本页编辑目标的 `.git` 是链接文件（linked / broken-gitlink）才渲染，普通仓库、bare 整组不画。展示 kind 一句话、主目录与来源（手动配置 / 自动找到 / 目录不在了），输入行 + 「保存」/「清除配置」走 `git/wt-main-save`；读数按仓库做模块级小缓存（进配置页或换目标才发，保存成功写回缓存），保存后面板级读数跟着重读。
- 「仓库」大组（多仓库）：与历史/变更页同一份清单（工作区扫描 + 手动登记，「＋ 添加目录」同一份持久清单、同一套报错话术）。单击行只换本页的编辑目标：组内收着的提交身份、远端、换行符三个下级组读写都改它（请求明说仓库路径，缺省 = 当前生效仓库），不改面板的生效仓库；加成功自动把新仓库选为编辑目标，移除的正好是目标时退回生效仓库；「已不存在」行只可移除、不可选中；名字/邮箱的半截草稿切目标即清。会话工作区不是仓库时这组照常可用。切换器收起时标题行显示本页编辑目标（✎ 短名），不再是生效仓库。
- 「会话完成时刷新 git 状态」（默认开）：会话跑完那一刻自动做一次 ⟳ 级别的整棵树刷新，chip 的分支名 / 改动数与变更、历史页跟着更新。
- 「所有会话都完成时自动推送」（默认关）：本页所有会话（含子代理会话）都停止运行且稳定 5 秒后，对当前生效仓库 push 一次（生效仓库是「仓库」组列表里带 ● 的那行，不随本页正在编辑的仓库走）；只推「领先远端且没有未解决冲突」的分支，失败只记录不重试，结果说在「最近一次自动推送」那行。这是后台自动化，不走推送前的确认弹窗。
- 提交身份的名字与邮箱只写本项目 `.git/config`（`--local`），默认空＝跟随全局，placeholder 显示全局那份的值；顶部「此刻生效」一行带来源文件，缺身份时红色提醒。
- 「清掉本项目覆盖，用回全局」对填过的键逐条 `--unset`（本来就没配也算成功）。
- 换行符 `core.autocrlf` 与 `core.safecrlf` 同样只写本项目，改动立即生效：autocrlf=true 检出转 CRLF、提交转回 LF，input 只在提交时转 LF，false 不转；safecrlf 是把关开关，换行转换不可逆时 true 让 git 拒绝、warn 只警告、false 不把关。每条旁边显示此刻生效的值与来源，选「跟随全局」＝清掉本项目的这条。
- 会话状态听的是 DSH 注入的会话 hook（每个会话常驻的 chip 在听，面板关着也在）；bridge 版／老版本没有这些 props 时两条开关不起作用，页面上会明说「当前环境不支持会话状态监听」。

## 全局配置（配置页 → 全局配置；原 Settings → dsh-git-idea配置）

- 原先自己占 DSH 设置面板的一页，2026-10 起搬进面板「配置」页，与「项目配置」并排成两档。

- 插件级配置写 `$DSH_HOME/dsh-git-idea.json`（默认 `~/.dsh/dsh-git-idea.json`），换浏览器一致；能不能写由当前会话的沙箱策略决定，写不进去时页面明说。
- 初始化仓库的默认分支（默认 `main`，引导页执行 `git init -b <值>`，留空用 git 自己的默认值）。
- cherry-pick 时记录来源（`-x`，默认关）。
- git 位置：装在 PATH 之外时可写绝对路径，旁边实时显示它解析到哪、什么版本、能不能跑。
- fetch 时删掉远端已删的远程分支（`--prune`，默认开）、pull 用 rebase（`--rebase`，默认关）、推送没有上游的分支时自动设上游（`push -u`，默认关，关掉时推送失败后面板问一句「推送并设为上游」）。
- 这三条网络项是面板给 git 的实参，不是 git 设置的副本，没勾的就是 git 原本的行为；「远程同步」组底部照实参写一遍会执行成什么。
- 「worktree」组（快捷命令之后）：「目录映射」多条编辑器，每条＝原目录＋替换目录（`worktreeDirMappings`，最多 50 条，交互同快捷命令组 —— 列表 + 编辑、删除两段式）。组内说明讲清用途：类似虚拟机挂载的目录映射，worktree 从别的机器整棵拷来、`.git` 里记的还是那台机器的路径（`D:/…`）时按前缀替换识别主目录（`D:/…` 与 `D:\…` 都认）。
- 会话完成刷新（默认开）与所有会话完成自动推送（默认关）在全局档和「项目配置」档是同一对开关。
- git 自己的配置（读写都走 `--global` 那份，即 `~/.gitconfig`）：全局配置的「提交身份」直接读写 `user.name` / `user.email`，先显示此刻生效的那一份和它的来源（`.git/config` 还是 `~/.gitconfig`），落点固定这台机器的 git 配置，不再选 `--local`（写本地归「项目配置」档）；空着的框一个字节都不写。
- 「换行符」组读写同一份 `--global` 里的 `core.autocrlf` / `core.safecrlf`：每条一行下拉，旁边显示当前全局值与来源，选中即写、首项「不设置」＝清掉 `--global` 的这条；DSH 不重启时宿主还没有这两条路由，那一组显示一行「重启 DSH 后才能读写」的说明。
- 浏览器级（只写当前浏览器 localStorage）：后台监测仓库变化并自动刷新（默认开，关掉后节奏选项一并失效）、面板打开时每 N 秒检查（默认 3，1–120）、面板关着时每 N 秒检查（默认 5，2–600）、面板关着时也监测（默认开）、悬停弹出分支切换卡片（默认开）、面板尺寸（可恢复默认）、变更页视图（树 / 扁平）、切换器记忆（可清除最近使用与收藏）。

## 刷新与性能

- 编辑器保存文件后约 1.5 秒自动刷新：订阅 DSH-better-sidebar（≥ 0.27.0）的文件保存事件（宿主半），命中已知仓库先失效读缓存，再按仓库尾沿防抖广播，浏览器走 ⟳ 那条整树刷新；该插件未装 / 版本过旧 / bridge 构建 / 路径不在已知仓库 / 没有浏览器连接，都是安静跳过零报错（见 [联动插件](./联动插件.md)）。
- 「工作区有几个改动」全局只有一份读数，chip 上那个数字就是面板「变更」页签上那个数字，两块屏幕不会各说各话。
- 一次仓库变动之后只问屏上那些路径，整棵树不在那条路上；折叠目录那条只问它自己，文件的所在目录留着（旁边新出现的文件靠它看见）。
- 量到一次路径读本身超过 1.5s 时，这个仓库整个收窄成只问那几条路径本身。
- 整棵树有自己的时钟：间隔 `max(30 秒, 8 × 上次耗时)`，上限 5 分钟；`⟳` 按钮永远立刻整棵树重读一次。
- 「本来干净、刚刚被改」的文件（以及干净目录里新出现的文件）任何路径读都看不见，只有整棵树读能看见，由上面的时钟兜着，`⟳` 是立刻拿到它的办法。

## 不注册工具

- 插件给 DSH 的只有 UI 和它自己的 RPC 通道：49 条 `host.call('git/…')`（面板、chip、配置页走的就是它们）。
- 不注册 8 个 git 工具（`git`、`git_status`、`git_log`、`git_diff`、`git_commit`、`git_branch`、`git_stash`、`git_sync`），省下每次请求约 1800 token 的 schema 和约 35% 只为它们存在的 Host 代码。
- 代价：`git_diff` 原先把差异渲染成 GUI 里的原生 diff 卡，现在记录里只有文本。

## 诊断与日志

- 看门狗自愈：面板 open 状态位是 `true`、根节点却已不在文档里（React 树崩了、body 级浮层被摘走）时，点 chip 先复位状态、重建浮层再重开（记 `watchdog-recovery`）；面板打开期间还有一只巡检眼，根节点消失 300ms 内自动修复。body 级浮层每次渲染都核对 `isConnected`，被摘走即换新 host，任何一次重渲染都能自愈。
- 崩溃 toast：面板树抛错被崩溃护栏（error boundary）圈住 —— 记 `crash` 日志、右上角弹 toast（原因 + 悬停展开堆栈；5 秒自动收、悬停不收、可点关、最多 4 条堆叠），open 状态位当场复位，下次点击是一次干净的打开。toast 是纯 DOM，不依赖面板那棵 React 树活着。
- 生命周期日志：`open`（来源）/ `close`（原因枚举：user-toggle / outside-click / esc / crash / programmatic）/ `crash`（message+stack）/ `watchdog-recovery`，带 ISO 时间戳；环形缓冲 200 条，镜像进 localStorage（`dsh.git-idea.client-log`），控制台输入 `__dshGitIdeaLogs()` 翻账；批量 POST 到宿主 `/api/dsh-git-idea/client-log`（同源、攒批、限频 2 秒 + 失败退避 30 秒、队列 500 条封顶），宿主追加写 `~/.dsh/logs/dsh-git-idea-client.log`（5MB 一转 `.1`）。宿主不在线时安静退回本地环。
- 宿主读耗时日志：每一条 RPC（49 条 `git/…`）记一行 tab 分隔账 —— ISO 时刻、方法名、仓库（payload.repo 或解析到的会话 cwd，拿不到 -）、paths 条数、耗时 ms、结局（ok / no=答复自带 ok:false / err=promise 拒绝 + 原话）—— 追加写 `~/.dsh/logs/dsh-git-idea-host.log`（5MB 一转 `.1`，stat 只问元数据）。追加异步攒批（2 秒）、失败安静（写不动只 console.error，读本身不受影响）。防刷屏：`git/watch` 成功且 <200ms 跳过，其余全记。
- 全局兜底：window 的 `error` / `unhandledrejection` 只上报堆栈或消息里自带 `dsh-git` 记号的错，宿主与别的插件的报错一个不劫持。
