# dsh-git-idea 被扩展说明

> 写给**其他插件 / 外部工具的作者**：如何发现并调用本插件暴露的 git 只读数据。
> 本插件不注册任何模型工具，也不要求消费方声明对本插件的强依赖 —— 两条通道都
> 可以「有则用、无则绕」。

## 概览

dsh-git-idea 把自己已经会回答的 git 问题整理成两份**只读**数据，通过两条通道暴露，
两条通道共用同一套构建函数（答案一字不差）：

| 通道 | 形态 | 适合谁 |
| --- | --- | --- |
| cordis 服务 | `ctx.get('dsh-git-idea')` 拿到服务对象，方法直接调用 | 同一 DSH 进程里运行的其他插件（推荐） |
| HTTP | `/api/dsh-git-idea/[功能路径]`，跟随 DSH 本体端口，返回 JSON | 脚本、面板之外的工具、跨进程的诊断程序 |

数据内容（`summary` 一次性聚合）：配置工作区里的仓库清单与数量、每个仓库的当前
分支 / 游离状态、upstream 与 ahead/behind、脏文件 / 暂存 / 未跟踪 / 冲突计数、
stash 条数、worktree 清单、分支与标签概要（总数 + 名单截帽）、远端名清单、HEAD
提交一行摘要。另有 `log`：多条件 git 日志查询，每条提交可带改动文件清单与增删
行数统计。

所有接口都是只读的：不 commit、不 checkout、不碰 stash、不改任何 git 配置
（面板交互路径自带的 safe.directory 兜底除外，见 62-panel.js，与本说明的 API
无关 —— 那是面板自己的行为）。

## 通道 A：cordis 服务（推荐）

本插件在 apply 时 `ctx.provide('dsh-git-idea', api)`。同一进程里的其他插件用
`ctx.get` 或 `inject` 拿到它：

```js
/* 消费方插件（cordis 插件形态） */
return {
  inject: ['dsh-git-idea'],          // 声明依赖：本插件会等 git-idea 就绪才 apply
  apply(ctx) {
    const git = ctx['dsh-git-idea']  // inject 之后属性就在 ctx 上
    const summary = await git.summary({ repos: ['/code/www/my/github/dsh-git-idea'] })
    const log = await git.log({ repos: ['/code/www/my/project'], authors: ['me@x.io'], limit: 20 })
  },
}
```

不想声明依赖的松耦合写法（服务可能不在 —— 本插件未安装、已停用、还没加载完）：

```js
function apply(ctx) {
  const git = ctx.get && ctx.get('dsh-git-idea')
  if (git === undefined || typeof git.summary !== 'function') {
    // 降级：走自己的路，不要假设 git 数据存在
    return
  }
  // inject 的形态同样可以：ctx.inject(['dsh-git-idea'], (scope) => { … })
}
```

服务对象的形状：

```js
{
  name: 'dsh-git-idea',
  apiVersion: 1,                    // 数据形状版本，见「版本兼容」
  summary(params) => Promise<对象>, // 聚合数据
  log(params) => Promise<对象>,     // 多条件日志查询
  manifest() => 对象,               // 自描述清单（路由表、apiVersion）
}
```

服务生命周期与本插件 fiber 绑定：本插件停用 / 重载期间 `ctx.get` 返回 `undefined`
（cordis 的 strict get 只认活着的提供方），消费方每次用之前查一次就好。

## 通道 B：HTTP

三条 exact 路由挂在本插件自己的 `ctx.inject(['webServer'], …)` 里，跟随 DSH 本体
端口，**没有独立端口**：

| 路由 | 方法 | 说明 |
| --- | --- | --- |
| `/api/dsh-git-idea/manifest` | GET | 能力清单：apiVersion、路由表（机器可读的发现口） |
| `/api/dsh-git-idea/summary` | GET / POST | 跨仓库只读聚合 |
| `/api/dsh-git-idea/log` | GET / POST | 多条件日志查询 |

- **POST** 必须同源（`Origin` 头的 host 与请求 host 一致，与面板 RPC 同一道门）；
  body 是 JSON 参数对象。
- **GET** 只收 query 参数，不设 Origin 门（同源 GET 本就不带 Origin 头；三条路由
  全是只读聚合）。带浏览器 cookie 的调用走 DSH 既有认证围栏；同机脚本直接
  `curl` 也可以。
- 答复一律 JSON；业务失败（不是仓库、超时、没有工作区…）也是 HTTP 200 +
  `{ok:false, error}`，只有「请求本身不合法」（坏 JSON → 400、方法不对 → 405、
  跨源 POST → 403）才用非 200。

```bash
# 发现
curl http://127.0.0.1:3080/api/dsh-git-idea/manifest

# 聚合：点名仓库
curl 'http://127.0.0.1:3080/api/dsh-git-idea/summary?repos=/code/www/my/github/dsh-git-idea'

# 聚合：扫工作区（显式给 workspace；不给且无会话时报 no-workspace）
curl 'http://127.0.0.1:3080/api/dsh-git-idea/summary?workspace=/code/www/my/github'

# 日志查询：作者 + 关键词（all-match）+ 路径 + 分页
curl 'http://127.0.0.1:3080/api/dsh-git-idea/log?repos=/code/www/my/proj&authors=me@x.io&grep=worktree&grep=面板&grepAll=true&paths=src/host&limit=20&skip=40'
```

GET 的数组参数（`repos` / `authors` / `grep` / `paths`）用**重复键**传多个值；
单数键（`repo` / `author` / `path`）是顺手糖，会并进对应的复数清单。布尔键收
`true` / `1`。POST 时 JSON body 优先，query 里带的值只补 body 没有的键。

## summary：数据结构

```jsonc
{
  "ok": true,
  "apiVersion": 1,
  "plugin": "dsh-git-idea",
  "generatedAt": "2026-11-07T09:00:00.000Z",
  "scope": { "mode": "repos", "workspace": null, "repos": ["/code/www/my/github/dsh-git-idea"] },
  "repoCount": 1,
  "reposOkCount": 1,
  "repos": [
    {
      "path": "/code/www/my/github/dsh-git-idea",
      "ok": true,
      "branch": "main",
      "detached": false,
      "upstream": "origin/main",
      "ahead": 2, "behind": 0,
      "sequencer": null,                    // "cherry-pick" | "revert" | "merge" | "rebase" | null
      "counts": { "staged": 0, "unstaged": 1, "untracked": 2, "unmerged": 0 },
      "stash": 0,
      "worktrees": [                        // 只含 `git worktree add` 出来的链接工作区
        { "path": "/tmp/wt-x", "head": "932f243f…", "branch": "feat-x",
          "detached": false, "bare": false, "locked": false, "lockReason": "",
          "prunable": false, "pruneReason": "" }
      ],
      "head": { "hash": "932f243f…", "short": "932f243", "date": "2026-11-06T11:16:59+08:00", "subject": "…" },
      "refs": {
        "branches": { "total": 4, "names": ["main", "feat-x"] },   // names 按最近提交排序、截帽 40
        "tags":     { "total": 0, "names": [] },                    // 同上，截帽 40
        "remotes":  ["origin"]                                      // 截帽 20
      }
    }
  ],
  "elapsedMs": 120
}
```

- `scope.mode`：`repos`（点名）| `workspace`（扫描）| `none`（没有会话也没有点名，
  此时 `error: "no-workspace"`）。
- 工作区模式额外带 `scan`：`{ repos, manual, missing, links, dirs, dirRepos }`
  —— 手动登记清单、已经不在的登记路径、`.git` 是文件的仓库（worktree/子模块）、
  登记「含仓库目录」与其子孙仓库的对应关系。
- 点名仓库超过 24 个时只读前 24 个，`droppedRepos` 说明丢了几个；个别仓库读失败
  时该行 `ok:false` + `error`（`timeout` / `no-git` / `unsafe-owner` /
  `not-a-repository` / ssh 通道的原话），**不影响其余仓库**。

## log：参数表

| 参数 | 类型 | 默认 | 说明 |
| --- | --- | --- | --- |
| `repo` / `repos` | string / string[] | 会话工作区 | 仓库，单个或多个（≤8）。服务调用不点名时用会话工作区；HTTP 不点名时必须给 `repos` 或 `workspace` |
| `workspace` | string | - | HTTP 专用：扫描/落点用的工作区路径（没有 sessionId 时的会话工作区替身） |
| `ref` | string | HEAD | 单个分支/ref；也接受 `a..b` 范围写法（git 自己认） |
| `from` / `to` | string | - | 范围两半，拼成 `from..to`（to 可达、from 不可达）；只给一半时另一半是 HEAD |
| `all` | bool | false | `--all`（与 ref/range 互斥，all 优先） |
| `authors` / `author` | string[] / string | - | 每项一个 `--author=`，多个取并集；默认字面量匹配 |
| `since` / `until` | string | - | 日期范围，git 认的任何写法（ISO、`2.weeks`…） |
| `grep` | string[] | - | 关键词，每项一个 `--grep=` |
| `grepAll` | bool | false | `--all-match`：多个 `--grep` 同时命中才算 |
| `regex` | bool | false | 关键词按扩展正则（`--extended-regexp`）；默认字面量（`--fixed-strings`）。只影响 grep 与 author 的匹配器 |
| `caseSensitive` | bool | false | 默认 `-i` 忽略大小写 |
| `paths` / `path` | string[] / string | - | `--` 之后的 pathspec 过滤 |
| `limit` | number | 50 | 上限 500（超出收敛到 500；非数字给默认） |
| `skip` | number | 0 | `--skip=`，上限 100000 |
| `includeFiles` | bool | true | false = 不带 `--numstat`（轻查询，`files` 为空数组但 `stats` 仍保留） |
| `detectRenames` | bool | true | false = 不带 `-M` |
| `firstParent` | bool | false | `--first-parent` |
| `merges` | string | - | `'only'` = `--merges`；`'exclude'` = `--no-merges` |
| `reverse` | bool | false | `--reverse` |

## log：数据结构

```jsonc
{
  "ok": true,
  "apiVersion": 1,
  "scope": { "mode": "repos", "repos": ["/code/www/my/proj"], "range": "main..dev", "all": false },
  "query": { /* 回显归一后的参数：limit=50、grep=[…] 等 */ },
  "repos": [
    {
      "repo": "/code/www/my/proj",
      "ok": true,
      "unborn": false,          // 仓库还没有任何提交时 true、commits 为空
      "commits": [ /* 与 commits 同形 */ ],
      "hasMore": true,          // max-count 多取了一条没回 —— 还有更多
      "outputTruncated": false  // stdout 撞了 4MB 帽时 true（末条提交已丢弃半条）
    }
  ],
  "commits": [                  // 多仓库时按作者日期倒序的合集；每条带 repo 字段
    {
      "repo": "/code/www/my/proj",
      "hash": "932f243f08b01…", "short": "932f243",
      "author":    { "name": "aogg", "email": "aogg@users.noreply.github.com", "date": "2026-11-06T11:16:59+08:00" },
      "committer": { "name": "aogg", "email": "aogg@users.noreply.github.com", "date": "2026-11-06T11:29:39+08:00" },
      "subject": "[auto] feat(git-idea): …",
      "body": "分支: main\n- …",
      "refs": "HEAD -> main, origin/main",
      "parents": ["dd30fa0…"],
      "files": [
        { "path": "src/client/50-log.js", "oldPath": null, "added": 87, "deleted": 21, "binary": false, "renamed": false },
        { "path": "docs/新名字.md", "oldPath": "docs/旧名字.md", "added": 2, "deleted": 1, "binary": false, "renamed": true },
        { "path": "assets/logo.png", "oldPath": null, "added": null, "deleted": null, "binary": true, "renamed": false }
      ],
      "stats": { "filesChanged": 3, "additions": 89, "deletions": 22 }
    }
  ],
  "commitCount": 2,
  "elapsedMs": 210
}
```

要点：

- **分页语义**：`limit`/`skip` 逐仓库生效（每仓各取自己的页），`hasMore` 也是
  每仓一个。跨仓库的全局分页没有干净的定义，这里诚实交回每仓自己的页；多仓
  `commits` 合集是并序展示用的，不要拿它做全局第 N 页。
- **merge 提交**默认没有 numstat（git 对 merge 不产 diff），`files` 为空数组；
  `merges:'only'` 时每条都是这样。要 merge 的文件统计需自定义工具。
- `added`/`deleted` 为 `null` 表示二进制文件。
- 性能保护：单仓超时 30s、stdout 4MB 帽、limit 帽 500。大仓库 + 大 limit 时
  numstat 是大头，先 `includeFiles:false` 探页再取详情是推荐姿势。
- 远程工作区（`ssh://alias/…` 路径的仓库）走本插件既有的 ssh 通道；
  dsh-ssh-workspace 不在场或通道未就绪时该仓库行 `ok:false` 并带原因。

## 版本兼容

- **数据形状版本**：`apiVersion` 目前是 `1`。语义化约定：只增字段不删字段不改
  语义 → apiVersion 不变；删字段 / 改字段含义 → 加一。消费方按 `apiVersion`
  决定能不能读，别按插件版本号。
- **DSH 版本**：本插件声明 `engines.dsh >= 0.1.5-rc.1`；HTTP 路由走的
  `webServer.register({kind:'exact'})` 与 cordis `ctx.provide` 在 0.1.5–0.3.x
  均可用（本插件面板自身依赖同一组接缝）。
- **通道缺失的降级**（都已内建，消费方只需处理「拿不到」）：
  - 本插件未安装 / 已停用：`ctx.get('dsh-git-idea')` 为 `undefined`；HTTP 404。
  - DSH 没有 webServer（无 web 界面的 headless 形态）：HTTP 三条路由不挂载，
    cordis 服务照常。
  - git 不在 PATH：各仓库行 `ok:false, error:'no-git'`。
  - ssh 远端仓库但 ssh 插件不在场：该仓库行 `ok:false` 并带通道原话。

## 降级建议（消费方代码）

```js
async function gitOverview(ctx) {
  const git = ctx.get && ctx.get('dsh-git-idea')
  if (git === undefined || typeof git.summary !== 'function') return null      // 服务不在
  try {
    const data = await git.summary({ sessionId: ctx.sessionId })               // 跟随会话工作区
    if (data == null || data.ok !== true) return null                          // 通道在、数据不在
    return data.repos.filter((r) => parseInt(r.counts.staged, 10) + parseInt(r.counts.unstaged, 10) > 0)
  } catch (error) {
    return null                                                                // ssh 通道等运行时失败
  }
}
```

不要缓存跨刷新的结论：所有数据都是「调用的那一刻」，插件的重载 / 会话切换都会
让旧答案过时。数值比较记得 parseInt/parseFloat（上面的示例就是照做的）。
