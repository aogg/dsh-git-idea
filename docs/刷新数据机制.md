# 刷新数据机制（dsh-git-idea）

> 各时机的行为细节见 [功能列表.md](./功能列表.md) 的「刷新与性能」等节。

## 自动刷新（不用动手）

- 会话完成时刷新：会话跑完那一刻自动做一次 ⟳ 级别的整树刷新，chip 与变更 / 历史页跟着更新（配置页开关，默认开）。
- 面板关着（甚至没有浏览器页面）时完成：宿主先把读缓存作废，下次打开面板读到的就是新账。
- 页面藏着时完成：那一刷记成欠账，页面回可见先补刷再对签名。
- 仓库签名轮询：宿主约 10 秒一轮看仓库签名，变了先失效缓存再广播（要有浏览器连着才跑）。
- 内置编辑器保存文件：保存后约 1.5 秒（同仓库尾沿防抖）按 ⟳ 那条路刷新。
- live 连接重连：先补欠账，再把手里每个仓库的签名对一遍。
- 页面回可见：除补欠账外，把各仓库签名对一遍，变了才刷。
- 变更页整树时钟：停在变更页时按 `max(30 秒, 8 × 上次整树耗时)`（上限 5 分钟）周期整树重读。

## 手动刷新

- 顶栏 `⟳`：立刻整棵树重读，打开的差异补丁一并换新账。
- 命令页「重新读取」按钮。

## 面板边界的重读

- 打开面板 / 切仓库：作废身份与分支两格缓存并补一次身份读（↑ 待推送数不许是旧缓存）。
- 变更类 git 命令成功后：暂存、提交、fetch、push 等重读；切分支、pull、合并 / 拣选 / 还原这类重写工作区的动作必须一次全树读。
- 命令页：切到该页、该页开着时仓库动过、命令开始 / 结束的实时推送，都会更新列表。
- 读到「不是仓库」的失败答复：面板可见时自动重问一次。

## 只读不刷的判定

- 自动推送前置判定：所有会话都停满 5 秒后读一次仓库状态，领先远端且没有未解决冲突才推（默认关）。
